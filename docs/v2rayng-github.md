# v2rayng github 发布页怎么读

查找 v2rayng github 安装文件，先打开仓库的 [Releases 页面](https://github.com/2dust/v2rayNG/releases)，查看对应发布条目下的资产列表。选包时看文件名里的设备架构，再区分安装包、签名和公钥文件。拿不准手机架构时，可按官方 wiki 的说明选择通用包。

## 从资产列表认出安装包

文件名可拆成软件名、版本号和架构三部分：`v2rayNG_<版本>_<架构>.apk`。结尾为 `.apk` 的是安装包；同名文件再接 `.sig`，则是配套签名。不要把签名文件当成安装包。

写这一页时(2026-11-08)，最新正式版为 `2.3.15`，发布于 `2026-11-01`。该版本的资产列表有二十一个文件，包括十个安装包、十个配套签名，以及一个公钥文件。看到多份文件时，要继续核对架构后缀，不能只看软件名相同就随便选。

带 `-fdroid_` 的文件是另一套包名的安装包。官方 wiki 将其用途解释为适配特殊系统设备，架构划分与标准包相同。这个后缀用于区分发布文件，不宜据此推断其他渠道的情况。

## 按设备架构选包

依据[官方架构说明](https://github.com/2dust/v2rayNG/wiki/Release-files-introduction-for-Android)，近几年主流手机和平板可选 `arm64-v8a`，对应六十四位 ARM。较旧手机或部分电视盒子若装不了六十四位包，可再试 `armeabi-v7a`，它对应三十二位 ARM。

电脑上的 Android 模拟器可按架构选择 `x86_64`，也可选择 `universal`。列表中的 `x86` 则供对应的 x86 设备使用。架构后缀说明适用设备，不能拿它判断版本新旧。

不清楚设备架构时，选包含全部架构的 `universal`，代价是文件更大。写这一页时(2026-11-08)，以 `2.3.15` 为例，通用包约为 `68.5 MiB`，`arm64-v8a` 包约为 `31 MiB`，前者体积约为后者两倍。

## 看发布标记，再核对文件

按 [GitHub 发布文档](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)的说明，`Pre-release` 通常表示尚未准备好投入生产使用，也可能存在不稳定情况。这是标记的含义，不能据此断言某个包一定存在问题。

写这一页时(2026-11-08)，该仓库曾将 `2.3.12`、`2.3.13` 标为预发布。阅读条目时，要把版本号与发布标记一起看，不能仅凭预发布字样判断它比正式版更新。

[仓库 README](https://github.com/2dust/v2rayNG)说明发布文件采用 GPG 签名，并列出供核对的公钥指纹。校验时，要同时认准安装包、它对应的签名和公钥；SHA-256 则可用于比对文件完整性。

> [!NOTE]
> 公钥名称是 `v2rayN-public-key.asc`，其中没有字母 G；每个安装包都有对应的 `.apk.sig`。发布文件的 SHA-256 信息可用于比对，但不能代替 GPG 签名校验。

## 常见问题

### v2rayNG 和 v2rayN 是同一个程序吗?

README 将二者区分为手机版与电脑版，作者均为 `2dust`。找手机安装包时，应查看 v2rayNG 仓库；公钥文件名称里出现 v2rayN，不代表进入了电脑版发布页。

### 安装前要看什么系统要求?

写这一页时(2026-11-08)，README 的系统要求徽章标为 `API 24+`。选包前先核对设备是否满足这一门槛，再按架构选择文件；系统要求和架构后缀需要分别确认。

### 从哪里进入发布文件列表?

README 给出的获取入口是 GitHub Releases。进入后展开对应条目的资产列表，找出适合设备架构的 `.apk`；需要校验时，再取同名签名及公钥，避免把这些配套文件认作安装包。
